## Prerequisites

| Requirement | Details |
|---|---|
| **GitHub Account** | Admin access to your `datagenix` repository |
| **Snowflake Account** | Active Snowflake account with appropriate role permissions |
| **API Integration** | `GITHUB_API_INTEGRATION` configured in Snowflake allowing `https://github.com/SonjeVilas/datagenix` (or user prefix) |
| **Snowflake Warehouse** | Dedicated warehouse (e.g., `COMPUTE_WH`) |
| **Database** | Target database (e.g., `ECOM_DB`) with target schema |
| **Python** | 3.12+ (managed by GitHub Actions runner) |

## Step 1: Configure GitHub Secrets

Navigate to your repository → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.

Add these **7 secrets**:

| Secret Name | Description | Example Format |
|---|---|---|
| `SNOWFLAKE_ACCOUNT` | Your Snowflake account identifier | `<org>-<account>` (e.g. `MYORG-MYACCOUNT`) |
| `SNOWFLAKE_USER` | Snowflake deployment username | `dbt_service_user` |
| `SNOWFLAKE_PASSWORD` | Snowflake user password | `••••••••••••` |
| `SNOWFLAKE_ROLE` | Snowflake role to execute dbt | `ACCOUNTADMIN` or `DBT_ROLE` |
| `SNOWFLAKE_WAREHOUSE` | Virtual warehouse to use | `COMPUTE_WH` |
| `SNOWFLAKE_DATABASE` | Target database | `ECOM_DB` |
| `SNOWFLAKE_SCHEMA` | Target schema | `RAW` |

> ⚠️ **Never** commit credentials to the repository. The pipeline uses `::add-mask::` to prevent credentials from appearing in logs.

## Step 2: Set Up Branch Protection

Navigate to → **Settings** → **Rules** → **Rulesets** (or **Branches**) → configure protection for `main`:

### Recommended Settings:

| Setting | Value |
|---|---|
| **Branch name pattern** | `main` |
| **Require a pull request before merging** | ✅ Enabled |
| **Required approvals** | `1` |
| **Require linear history** | ✅ Enabled |
| **Block force pushes** | ✅ Enabled |
| **Require status checks to pass** | ✅ Enabled |
| **Required status checks** | `SQLFluff Lint`, `dbt Compile & Build`, `Python Tests (pytest)` |

This ensures:
- **Every PR requires maintainer review** (via `.github/CODEOWNERS`)
- **All automated checks must pass** before merge is allowed
- **No direct pushes** to `main`

## Step 3: Verify Snowflake Integration

Verify your Snowflake `GITHUB_API_INTEGRATION` allows the `datagenix` repository prefix:

```sql
-- Check API integration and allowed prefixes
SHOW INTEGRATIONS LIKE 'GITHUB%';
DESC INTEGRATION GITHUB_API_INTEGRATION;

-- If API_ALLOWED_PREFIXES was pinned to an older URL, update it:
ALTER API INTEGRATION GITHUB_API_INTEGRATION
  SET API_ALLOWED_PREFIXES = ('https://github.com/SonjeVilas/');

-- Verify permissions
SHOW GRANTS ON INTEGRATION GITHUB_API_INTEGRATION;
```

The CD pipeline (`scripts/snowflake_deploy.py`) will automatically:
1. Create the Git Repository object (`DATAGENIX_REPO`) if it doesn't exist
2. Fetch latest code from GitHub
3. Create/replace each dbt Project discovered in `generated_projects/`
4. Execute `dbt build` natively inside Snowflake

### 4.3 Verify

- Review **Python Tests (pytest)**, **SQLFluff Lint** annotations, and **dbt Compile & Build** results
- Confirm branch protection enforces passing checks before merging

## Step 5: Test the CD Pipeline

After CI passes and the PR is approved:

1. **Merge** the PR into `main`
2. The CD pipeline triggers automatically
3. Check **Actions** tab for `CD – Deploy to Snowflake`
4. Verify in Snowflake:

```sql
-- Check the Git Repository was created
SHOW GIT REPOSITORIES IN SCHEMA ECOM_DB.RAW;

-- Check deployed dbt Projects
SHOW DBT PROJECTS IN SCHEMA ECOM_DB.RAW;

-- Verify the data in marts
SELECT * FROM ECOM_DB.RAW_MARTS.DIM_CUSTOMERS LIMIT 10;
SELECT * FROM ECOM_DB.RAW_MARTS.FCT_ORDERS LIMIT 10;
```

## Pipeline Details

### CI Pipeline (`.github/workflows/ci.yml`)

| Job | Steps | Purpose |
|---|---|---|
| **python-tests** | `pytest tests/ -v` | Validates core agents, orchestrator, validator, and security controls |
| **lint-sql** | SQLFluff lint | Static analysis of Snowflake SQL models across `generated_projects/` |
| **dbt-validation** | deps → parse → compile → build | Full dbt validation against Snowflake (runs offline `dbt parse` on fork PRs without secrets) |

**Triggers:** Pull requests targeting `main` and pushes to `main`.

### CD Pipeline (`.github/workflows/cd.yml`)

| Step | Description |
|---|---|
| **Create Git Repo** | `CREATE GIT REPOSITORY IF NOT EXISTS ... DATAGENIX_REPO` (idempotent) |
| **Fetch** | `ALTER GIT REPOSITORY ... FETCH` pulls latest code |
| **Create dbt Project** | `CREATE OR REPLACE DBT PROJECT` from Git stage |
| **Execute** | `EXECUTE DBT PROJECT ... ARGS = 'build'` |
| **Report** | Query history & step summary |

**Triggers:** Push to `main` (after merge) that modifies `generated_projects/**`, `scripts/snowflake_deploy.py`, or `.github/workflows/cd.yml`.

### Deployment Script (`scripts/snowflake_deploy.py`)

The Python script handles:
- Automatic discovery of all projects under `generated_projects/` (or targets a single path via CLI arg / `DBT_PROJECT_PATH`)
- Secure credential management via environment variables
- Idempotent object creation (`IF NOT EXISTS`, `OR REPLACE`)
- JSON results artifact (`deploy_results.json`) & GitHub Actions step summary reporting

## Troubleshooting

### CI: Fork PRs do not have Snowflake credentials
GitHub Actions withholds repository secrets from external fork PRs for security. In this case, `dbt-validation` automatically falls back to offline `dbt parse` validation so open-source contributors are not blocked by missing secrets.

### CD: "Git repository fetch failed" or prefix denied
- Verify `DESC INTEGRATION GITHUB_API_INTEGRATION;` includes `https://github.com/SonjeVilas/` or `https://github.com/SonjeVilas/datagenix`.
- Ensure the GitHub repo URL in `.github/workflows/cd.yml` matches your renamed repository (`https://github.com/SonjeVilas/datagenix.git`).

### CD: "dbt Project creation failed"
- Confirm `dbt_projects_profiles.yml` and bundled `dbt_packages/` are committed for the project being deployed (Snowflake native dbt cannot download external packages at runtime).

## Security Considerations

| Measure | Implementation |
|---|---|
| **Credentials in GitHub Secrets** | Never hardcoded; always loaded from `${{ secrets.* }}` |
| **Log masking** | `::add-mask::` hides credentials in workflow logs |
| **profiles.yml** | Generated dynamically in CI; real files are `.gitignore`d |
| **CODEOWNERS** | Changes reviewed by maintainers listed in `.github/CODEOWNERS` |
| **Branch protection** | No direct pushes to `main`; CI must pass |
| **Idempotent deployment** | `IF NOT EXISTS` and `OR REPLACE` prevent duplicates |
